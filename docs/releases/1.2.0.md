# Notchlight 1.2.0

Adds native small and medium desktop widgets and improves the reliability and background cost of the local Codex integration. The medium widget uses two rings when two supported allowances are available, or one centered ring when only one is available. Widgets always show remaining usage, reset information, and recently observed activity. Missing data and expired values have explicit unavailable/stale states; allowance durations are not inferred to be calendar months.

## Reliability and background work

- Known session files remain readable during a temporary missing-WAL gap, so task completion can still stop the working indicator. Initial discovery, desktop restart, and database/schema failures continue to report unavailable. Existing lifecycle freshness limits remain in effect.
- Bounded log tails discard an expected first-record fragment. Oversized partial records resume at the next newline, and large appends preserve known lifecycle state without resetting its freshness deadline.
- Ordinary catalog changes coalesce for up to five seconds. Existing session events keep their short delivery window, and unknown sessions request prompt discovery.
- Healthy idle usage refreshes every five minutes; active work and recovery refresh about once per minute. Starting work advances a pending idle refresh. Manual refresh remains available.
- Each helper RPC has its own monotonic timeout budget. A timed-out read-only rate-limit request retries once on the same helper before reporting failure.
- The notch menu uses screen coordinates instead of attaching menu tracking to a passive panel.
- Widget app-group resolution runs on the writer actor rather than during main-actor initialization.
- The Settings preview clears paths during empty initial layout instead of trimming a degenerate path.

## Validation

The complete Swift test suite passed: **197 tests**, including regressions for WAL gaps, restart invalidation, completion during a gap, catalog coalescing, large/partial records, RPC timing/retry/cancellation, preview startup layout, widget freshness/account changes, publication ordering, and URL routing.

The extracted release ZIP passed strict deep signature verification, host/extension version and build checks, matching app-group entitlements, extension sandboxing, arm64 architecture, macOS 14 minimum load commands, legal-resource checks, and its SHA-256 checksum. The packaged host recorded successful activity and usage reads. A separately signed sandboxed probe read a connected, valid shared snapshot written by that host. PlugInKit registered the 1.2.0 extension.

Synthetic widget fixtures were visually inspected in light, dark, and accented appearances. The fixture includes single/dual allowances and loading, unavailable, disconnected, sign-in, idle, working, and stale states. Monthly examples are synthetic. An accented fixture does not prove WidgetKit's actual system rendering.

Computer Use's native pipe failed after relaunch, including after a reset and exact-path retry. Consequently no fresh manual menu, Settings, desktop placement, widget-gallery, or widget-click acceptance is claimed for this release. Earlier installed-widget validation is documented separately in `docs/widgets.md`. macOS 14/26 runtime, Intel, and VoiceOver navigation remain unverified. No new full-app CPU, battery, or percentage improvement is claimed.

## Download

`Notchlight-1.2.0-macOS-arm64.zip` and `SHA256SUMS.txt` are the release assets. This build is **Apple Development signed and not notarized**; it is not a Developer ID distribution. macOS may require explicit user acceptance on first launch. Both host and extension use matching team-backed app-group entitlements.

Launch the host once, then open macOS's Edit Widgets gallery and search for Notchlight Usage. WidgetKit controls refresh delivery; the widgets are not real-time task monitors.
