# Notchlight 1.2.2

Restores widget updates and reduces memory used when exporting diagnostics.

- **Reliable widget packaging.** The host and widget extension share the same
  signed app group. Packaged builds require a team-backed signing identity and
  verify signatures, matching teams and versions, shared-group configuration and
  entitlements, and the extension sandbox. Only a verified bundle replaces the
  existing app; the prior bundle is preserved in a backup.
- **Lower-memory diagnostics export.** Logs are read incrementally, with a compact
  record index and resource/state summaries. Report text and exported log files
  are preserved, including sorting, corruption accounting, and exact operation
  percentiles.
- **Fewer shortcut conflicts.** Removed the explicit Settings and Show Border
  shortcuts and all notch-menu key equivalents. Standard macOS window, text
  editing, and app Quit commands remain available while Notchlight is active.

## Validation

All **200 Swift tests** and **seven packaging contract tests** passed. Signed
release packaging and the widget signing/group/sandbox gate passed. The extracted
archive was checked for signature integrity, matching host/extension version
**1.2.2 / build 9**, arm64 architecture, macOS 14 minimum, legal resources, and its
SHA-256 checksum.

Three matched optimized full-export runs per implementation used the same
**47.44 MiB** snapshot: 14 files and 67,307 diagnostic events. Median peak memory
footprint fell from **407.81 to 63.91 MiB (84.33% lower)**. Median export time rose
from **1.552 to 1.977 seconds** because the reader decodes records in two passes.
All six archives passed integrity checks and had byte-for-byte identical reports
and raw log files. These are isolated export-process measurements on arm64 macOS
27.0.1 with Swift 6.4; whole-app memory, energy, and battery improvements have not
been measured.

The restored signed app writes fresh snapshots to its shared widget container,
and macOS registered its rebuilt extension. Fresh visual widget-refresh inspection
remains unverified because the native UI tool's connection failed. Runtime
coverage on macOS 14/26 and Intel remains unverified.

Local verification evidence is in `build/release-1.2.2/`,
`build/widget-signing-fix/`, and `build/diagnostics-export-opt/`.
