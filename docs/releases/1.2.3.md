# Notchlight 1.2.3

Less background work during sleep and faster Codex activity tracking.

- **Sleep-aware usage refreshes.** Pending and in-flight requests stop when the
  Mac sleeps. Notchlight preserves the last successful usage and refreshes on
  wake. Late results from cancelled requests cannot replace newer data.
- **Faster activity-log reads.** The reader decodes only lifecycle metadata,
  scans each buffer once, and reuses date formatters within each batch. It keeps
  support for partial records, cancellation, malformed input, and file changes.
- **Fewer database retries.** Temporary missing-WAL gaps no longer trigger an
  extra retry loop when cached sessions and native file notifications remain
  usable. File events and the existing safety reconciliation handle recovery;
  cold catalogs and unavailable watchers retain bounded retries.

## Performance and validation

Three release benchmark trials per implementation used the same synthetic
**7.9 MiB** log, with five fresh-reader reads after a warmup. Median time per
read fell from **938 ms to 71 ms (13.2× faster)**; CPU time fell **92.4%**.
In three cached-WAL trials, extra queries fell from **2 to 0** during each
12-second interval. Native-event recovery remained around **0.27 seconds**.
Interrupt wakeups were unchanged in that short test.

These measurements isolate the activity reader on an Apple M5 Pro running
macOS 27.2 with Swift 6.4.2. They do not establish whole-app CPU, energy, or
battery-life improvements. A missed catalog notification can wait for the
existing safety reconciliation, about once per minute.

All **209 Swift tests** and **seven packaging contract tests** passed. The signed
release archive was checked for signature integrity, matching host/extension
version **1.2.3 / build 10**, shared-group entitlements, extension sandboxing,
arm64 architecture, macOS 14 minimum, bundled legal files, and SHA-256 checksum.

Sleep tests exercise the notification handlers with an isolated notification
center; physical system sleep was not exercised. Runtime behavior on macOS
14/26 and Intel remains unverified. No UI/layout changes are included.
