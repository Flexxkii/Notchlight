# Notchlight 1.2.1

Reduces diagnostic log storage and makes activity diagnostic outcomes clearer.

- Resource samples retain CPU, memory, disk I/O, wakeup counters, and the activity,
  window, and overlay state needed to interpret each measurement. The two-second
  cadence is unchanged. Display geometry and appearance settings record when
  they change and in a full context checkpoint every minute.
- Successful reads of known session files during a temporary missing database WAL
  report success, with database availability recorded separately. Catalog queries
  still identify the WAL gap; genuine activity unavailability remains explicit.

## Validation

All **198 regression tests passed**, including compact sample fidelity, full
context checkpoints, reports after earlier context records are removed, and
successful cached activity reads during WAL gaps with restart invalidation.

An optimized recorder comparison used the same captured display/appearance
context, 601 resource samples, simulated two-second intervals, and identical
working/idle transitions. The before/after resource and state reports matched.
Log storage fell from **1,102,969 to 878,637 bytes (20.34%)** for that fixture.
This is a measurement of recorded bytes in a controlled fixture; the reduction
for a whole live session varies with other events. CPU and battery improvements
have not been measured.

The release ZIP passed strict deep signature verification, host/extension version
and build checks, matching app-group entitlements, widget sandboxing, arm64
architecture, macOS 14 minimum load commands, legal-resource checks, and its
SHA-256 checksum. The RPC suite also passed after updating client version metadata.
The relaunched host recorded successful usage and activity operations without
recorder failure events. One Apple BaseBoard task-port lookup message appeared;
no accompanying app failure or source cause was established.

Local evidence is in `build/log-audit-2026-10-08/`. Runtime coverage on macOS 14/26
and Intel remains unverified. No visual behavior changes are included. Computer
Use's native pipe failed after app relaunch, including after a reset and an exact
path retry; no fresh manual Settings/menu inspection is claimed.
